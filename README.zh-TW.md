# pi-translator-live 【焚诀】

[English](README.md)

[pi](https://github.com/earendil-works/pi) 的即時翻譯擴充套件：你的輸入會被翻譯成**輸出語言**（主模型思考與回覆所用的語言），而模型的回覆會以你的**輸入語言**（你的閱讀語言）顯示。工作階段歷史保留原文；翻譯僅用於顯示，完全不影響模型實際看到的內容。

- 自動偵測來源語言——用任何語言輸入都可以
- 雙向翻譯：輸入→輸出、回覆→顯示兩個方向可分別開關（`/translator input` 只翻譯輸入）
- 顯示翻譯：回覆生成期間顯示本地化的「翻譯中…」佔位；回覆完成後，通過驗證的譯文才取代原文區段。這不是逐 token 的串流翻譯。
- Markdown 語法、程式碼、連結目標與可辨識的技術字面內容在本地保持不變
- 翻譯由獨立、可自行選擇的模型執行，主模型設定不受影響
- 輸入方向 fail-closed：翻譯失敗就不會送出，原稿會回到編輯器
- 顯示翻譯只存在記憶體中；已印出的終端歷史不會重繪

## 最新改進

### 0.1.4：單一佇列

- 所有翻譯工作都經過單一 FIFO 佇列——與 OMP 版本相同的機制——長回覆翻譯不會再與輸入翻譯並發。
- 互動輸入優先於排隊中的回覆工作：你的訊息先翻譯，回覆翻譯隨後。取消時整個佇列一併拒絕。

### 0.1.3 修復

- **含斜線的譯文被誤判拒絕。** 當模型把 `backup/rollback` 這類文字翻譯成中文、日文、阿拉伯文等語言時，譯文（斜線後接中日韓文字，或結尾帶阿拉伯標點 `،`/`؛`）可能被誤判為受保護的檔案路徑，導致保護驗證丟棄整則回覆翻譯、改顯示原文。現在路徑判定需要明確證據——根路徑、副檔名、已知目錄、數字或多個斜線——與文字語種無關。
- **保護失敗可診斷。** 翻譯被拒的日誌現在包含出問題的片段（`span N: "…"`），單看 `translator.log` 即可定位原因。

### 0.1.2：解析器式翻譯

- **先解析，只翻譯文字**：以開源 mdast + GFM 解析取代由模型攜帶的 XML 標記，不再要求模型正確複製 Markdown 或受保護字面內容。
- **本地重建，整份發布**：文字單元分別翻譯後放回原始來源，並與原始 Markdown 結構比對；全部通過才顯示。
- **混合文字修正**：一般斜線複合詞仍可翻譯；強調標記邊界使用字元參照，保留格式且不增加可見空格。
- **驗證依據**：標準 OMP 實作已通過解析器回歸測試與歷史 HyMT2 重播。這些是 OMP 結果，不代表新遷移的 Pi 執行期已通過煙霧測試；詳見[驗證](#驗證)。

## 安裝

```bash
pi install git:github.com/kid0114/pi-translator-live
```

然後啟動新的 pi 程序。套件安裝時會自動安裝 mdast/GFM 解析器相依套件，無需另外設定。首次進入互動工作階段時會出現一次性選擇器，請選擇預設翻譯模型；選擇會存入 `~/.pi/agent/translator.json`。

免安裝試用：

```bash
pi -e git:github.com/kid0114/pi-translator-live
```

鎖定發行版本而非追蹤 master：

```bash
pi install git:github.com/kid0114/pi-translator-live@v0.1.4
```

更新 / 移除：

```bash
pi update --extensions
pi remove git:github.com/kid0114/pi-translator-live
```

## 需求

- pi ≥ 1.1.0
- pi 模型註冊表中至少一個已認證模型。你現有在用的模型都可以——託管的 OAuth 模型或本地 OpenAI 相容端點（在自己的 `models.json` 中設定）皆可。便宜快速的模型（例如 Gemini Flash 級別）最適合做翻譯。

## 首次執行

安裝後的第一個互動工作階段會出現一次性選擇器，請你選擇預設翻譯模型（推薦的輕量模型會標註）。選擇會存入 `~/.pi/agent/translator.json`。按 Esc 取消則本次使用內建啟發式選擇，下次啟動時會再詢問。

## 使用方式

翻譯預設為啟用。指令一覽：

| 指令 | 效果 |
|---|---|
| `/translator` 或 `/translator both` | 啟用輸入 + 回覆翻譯 |
| `/translator input` | 只翻譯輸入；回覆維持輸出語言 |
| `/translator off` | 關閉；進行中的翻譯會取消 |
| `/translator original` | 檢視最近一則完成回覆的原文（唯讀檢視器） |
| `/translator model [關鍵字]` | 本次執行切換翻譯模型（省略時開啟選擇器） |
| `/translator default [關鍵字]` | 同上，但儲存為預設值 |
| `/translator default clear` | 清除已儲存的預設模型 |
| `/translator default input [語言]` | 設定回覆的**顯示語言**（例如 `zh-TW`） |
| `/translator default output [語言]` | 設定**主模型語言**（例如 `en`） |

> 命名說明：`default input` 選的是回覆**顯示**的語言；`default output` 選的是你的輸入被翻譯**成**的語言，也就是主模型回覆所用的語言。

語言參數接受代碼（`en`、`zh-CN`、`zh-TW`、`ja`……）或英文名稱；省略參數則開啟選擇器。內建 33 種語言。

輸入翻譯進行中可按 Esc 取消。

## 選擇翻譯模型

### 本地模型（有條件時推薦）

本地模型讓文字不離開你的機器。延遲取決於文件長度、模型大小、硬體與伺服器負載。任何 OpenAI 相容伺服器都可以——llama.cpp、LM Studio、vLLM、SGLang、Ollama，或 MLX 伺服器。

在你自己的 `~/.pi/agent/models.json` 中註冊端點：

```json
{
  "providers": {
    "local-translator": {
      "baseUrl": "http://localhost:PORT/v1",
      "api": "openai-completions",
      "apiKey": "local",
      "models": [{ "id": "<伺服器預期的模型 id>" }]
    }
  }
}
```

注意事項：

- 即使伺服器不驗證身份，pi 也要求填寫 `apiKey`——填 `"local"` 之類的虛設值即可。不填的話 pi 不會把該供應商列為可用。
- 伺服器必須接受 `system` 角色訊息（翻譯指令），以及一則包含文字單元的 `user` 訊息，並只回傳該單元的譯文。

設定後執行一次 `/translator default local-translator/<模型 id>` 即可儲存。

### 沒有本地模型

直接使用你在 pi 中已認證的託管模型——無需額外設定，它就會出現在 `/translator model` 中。建議選便宜、快速、非推理型的模型（Gemini Flash 級別或類似者）：每次輸入和每則回覆都會觸發翻譯，重型推理模型只會增加延遲與 token 成本。內建的預設啟發式邏輯在首次執行時已優先選擇這類模型。

## 運作原理

- **輸入方向（fail-closed）**：你的文字在送出前翻譯成輸出語言。翻譯失敗時不送出任何內容；只有目前請求仍有效且編輯器為空時才還原原稿，不覆蓋較新的草稿或其他工作階段。指令、`!shell`、路徑、程式碼一律不翻譯。
- **顯示方向（完整原文回退）**：回覆生成期間顯示「翻譯中…」；定稿後先翻譯並驗證完整回覆，再由 Markdown 顯示轉換發布。歷史記錄與主模型收到的內容不變。失敗時顯示完整原文（包含原始表格儲存格），僅在回覆外顯示一則分類狀態，不在段落或儲存格塞入失敗文字或計數。
- 系統提示掛鉤會要求主模型以輸出語言撰寫回覆，同時保留你的任務、程式碼、路徑與工具參數。
- **先解析為文字單元**：以 `mdast-util-from-markdown` 加上 GFM 在模型呼叫之前解析來源。只有可翻譯文字區段會成為單元；同一翻譯工作中的相同單元共用請求，不同單元依序翻譯。只有程式碼／字面內容時不需呼叫模型。不使用由模型攜帶的 XML 包裝、複製標記協定或選擇性片段重試協定。
- **原始來源留在本地**：原始 Markdown 分隔符號、區塊順序、表格版面、換行格式、程式碼、連結目標／參照 ID，以及可辨識的指令、路徑、URL 與其他技術字面內容都留在用戶端。明確連結的標籤可翻譯，但不改變目標。字面內容留在原始位置，不由模型換序。
- **重建與驗證**：譯文先跳脫為純文字，再放回原始來源區段。最終文件會再次解析；Markdown 結構與受保護字面值必須與原文一致，才接受整份輸入／回覆。文字遺漏、新增技術字面內容或結構改變，都會拒絕整份結果。重建後的原始 Markdown 可能在強調分隔符號旁出現字元參照；渲染後仍是一般字元，不會增加可見空白。
- 一般單斜線複合詞（包括 `類型/reputation` 之類的混合文字）在沒有明確路徑依據時視為可翻譯文字。這刻意讓有歧義的裸複合詞優先參與翻譯；若路徑或技術詞彙有歧義，請以行內程式碼明確保護。
- 每個請求各自持有取消訊號與 **60 秒輸出閒置計時器**。收到第一個非空文字、思考或工具呼叫增量後才開始計時；空心跳不重設計時。排隊與預填充沒有擴充套件期限，但供應商傳輸與重試限制仍適用。
- 模式、工作階段、模型或語言改變時會取消舊工作，阻止過期快取更新。較新的互動輸入會取代較早仍在等待的輸入。
- 請求經由單一佇列序列化，互動輸入優先（與 OMP 版本相同機制）。跨工作階段公平排程與非同步分片仍**尚未實作**。
- Pi 的 Markdown 轉換介面沒有訊息或區塊識別碼，顯示快取只能用語言與去除外圍空白的原文作為鍵；不同於 OMP 的訊息識別快取，相同文字在不同上下文產生不同譯文時，Pi 顯示介面無法各別定位。

## 驗證

```bash
node --experimental-strip-types --test extensions/translator/translator-core.test.ts
```

核心回歸測試涵蓋來源區段還原、GFM 表格／工作清單、巢狀 Markdown、Unicode 位移、程式碼與技術字面內容、連結目標、斜線複合詞、強調邊界、模型標點跳脫，以及文字遺漏或不安全時的整份拒絕。上方指令執行 Pi 套件的 Node 測試；解析器相依套件由套件管理器安裝。

**已驗證的 OMP 結果（2026-10-15）**：標準 OMP 解析器核心通過 22 項回歸測試。解析器修正後，10 月 13–14 日記錄的 40 個 HyMT2 失敗案例全部以快取譯文成功重建；首次重播曾失敗的九例，加上一例較早的 10 月 10 日逾時案例，合計 10 例真實模型重新重播也全數通過。新啟動的已安裝 OMP 18.10.3 程序另以 35.805 秒完成一則 5,715 字元歷史回覆的翻譯，原文檢視器仍保留英文來源。新啟動的隔離 Pi 1.2.0 終端也載入此套件與本地 HyMT2 端點：英文助理回覆顯示為繁體中文，`/translator original` 保留英文來源。結構驗證不保證翻譯品質。

Pi 直接等待擴充套件處理器，沒有 OMP 式的處理器逾時選項。維護中的 OMP 處理器使用 `{ timeoutMs: 600000 }`；這是有限的主機期限，與每個請求的輸出閒置計時不同，也不是 Pi 供應商選項。


## 疑難排解

翻譯失敗以 JSON 行記錄到 `~/.pi/agent/translator.log`，包含方向、目標語言、模型、耗時、`category` 與原因；保護檢查失敗另含 `protectionCode`。擴充套件不記錄原文或譯文。回覆翻譯失敗時顯示完整原文，不保留部分譯文。

修改擴充套件檔案或更新套件後，須退出 Pi 並啟動新程序才會載入新模組。沒有自動熱重載：切換翻譯模型或開關翻譯不會重新載入原始碼。

- `idle-timeout`：輸出已開始，但連續 60 秒沒有進展
- `provider-timeout` 或 `provider`：供應商或傳輸層失敗；單純排隊不是擴充套件逾時
- `completion`、`language` 或 `protection`：回覆未完整結束、仍有未翻譯文字、譯文不安全，或重建／Markdown 結構違規。顯示完整原文，絕不發布部分譯文。
- 輸入被拒並出現警告 → 找 `"direction":"input"`；不送出內容，且不覆蓋較新的編輯器草稿
- `/translator original` 隨時可檢視最近一則完成回覆的原文

## 隱私

你的輸入與模型回覆會傳送給你所選的翻譯模型。在意這點的話請選用本地端點。除此之外不會傳送任何資料；本套件只在你自己的 pi 代理目錄中儲存偏好設定（`translator.json`）與可選的診斷日誌（`translator.log`）。
